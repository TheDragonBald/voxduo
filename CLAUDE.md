## Что это за проект

**VoxDuo** — настольное приложение для Windows: распознавание речи (голос → текст)
и синтез речи (текст → голос) на русском языке. Автор пользуется им ежедневно и
выкладывает в открытый доступ, чтобы пригодилось другим.

Выросло из одного файла `voice_to_text.py` (113 строк, Tkinter + openai-whisper
`small` на CPU). Исходник сохранён в `legacy/` как отправная точка истории.

Репозиторий: `github.com/TheDragonBald/voxduo` (публичный, GPL-3.0).

## Процесс работы с git

С 7 сентября 2026 — по ветке на этап, ничего не коммитится прямо в `main`:

1. **Ветка на этап**: `git switch -c stage-N-краткое-имя`
2. **Работа + коммиты** внутри ветки, `just all` перед каждым
3. **PR**: `gh pr create --base main` — заголовок английский, тело русское,
   2–3 предложения по существу, без подписей и вотермарок
4. **Пауза на ревью.** Мержить только по явной команде пользователя;
   «ок» и молчание командой не считаются
5. **Squash merge**: `gh pr merge N --squash --delete-branch`
6. **Чистка**: `git switch main` → `git pull` → убедиться, что ветка удалена
7. **Обновить контекст**: чекбоксы в `PLAN.md`, журнал и уроки в `CLAUDE.md`

Так на каждом этапе есть точка отката, а история `main` состоит из
осмысленных законченных шагов.

Репозиторий: `github.com/TheDragonBald/voxduo`, ветка по умолчанию `main`.

## Ключевые решения и почему именно так

- **`faster-whisper` вместо `openai-whisper`.** Те же веса, движок CTranslate2:
  кратно быстрее, встроенный Silero VAD. `torch` из пути распознавания уходит совсем.
- **Модели `large-v3` и `large-v3-turbo`**, переключатель в интерфейсе.
  Корень прежних проблем с качеством — `small` на CPU, а не предел Whisper.
- **GPU через pip.** `nvidia-cublas-cu12` и `nvidia-cudnn-cu12` публикуют
  win_amd64 колёса; CUDA Toolkit не нужен. Документация faster-whisper на этот
  счёт устарела. DLL регистрирует `voxduo/cuda_setup.py` **до** импорта
  `faster_whisper` — иначе «Could not locate cudnn_ops64_9.dll».
- **Три движка TTS с цепочкой фолбэка:** edge-tts (онлайн, самый живой) →
  Silero → Piper. edge-tts периодически отдаёт 403 при ротации токена Microsoft,
  поэтому единственным быть не может.
- **Лицензия GPL-3.0.** Выбор продиктован `piper-tts` (GPL-3.0): импорт делает
  наш код производной работой. Альтернатива с MIT потребовала бы выносить Piper
  в отдельный процесс.
- **Модели по умолчанию — лицензионно чистые:** Whisper MIT, Silero
  `v5_cis_base` MIT (не `v5_5_ru`, тот CC-BY-NC), Piper `denis`/`dmitri` CC0
  (не `ruslan` — BY-NC-SA, не `irina` — лицензия не указана).
- **Логи есть, но без текста расшифровок.** Пишем длину, длительность, модель,
  время. Содержимое речи — только под `--debug`, осознанно и временно.
- **Тесты — только на чистой логике:** `history`, `config`, `postprocess`,
  реестр TTS. Интерфейс и реальные вызовы движков не тестируем, для них
  `scripts/smoke.py`.

Подробное обоснование каждого пункта — в `PLAN.md`.

## Команды

Всё делается через `just` (установлен, 1.57.0). Прямые вызовы `python` не
использовать: в PATH лежит Python 3.14 без пакетов, и запуск оттуда падает
невнятной ошибкой импорта. `just --list` показывает полный список.

| Команда                   | Что делает                                             |
| ------------------------- | ------------------------------------------------------ |
| `just run` / `just debug` | запуск, обычный и с подробными логами                  |
| `just check`              | сводка окружения: версии, видеокарта, пути             |
| `just test` / `just cov`  | тесты, с покрытием                                     |
| `just lint` / `just fmt`  | ruff: проверить, отформатировать и починить            |
| `just all`                | lint + test — прогонять перед каждым коммитом          |
| `just smoke`              | живой прогон всех движков синтеза (сеть, модели, звук) |
| `just install-*`          | установка: базовая, gpu, silero, dev                   |
| `just build`              | сборка `voxduo.exe`                                    |
| `just logs`               | открыть папку с логами                                 |

Ruff настроен в `pyproject.toml`: длина строки 100, правила E/F/W/I/UP/B/SIM.
`E501` отключён осознанно — перенос по ширине рвёт русские комментарии в
неудобных местах, длину держим глазами.

## Выученные уроки

Практические грабли этой среды. Пополнять при каждой новой находке.

- **Папку проекта нельзя переименовать во время сессии.** Она — рабочая
  директория, Windows держит её занятой (`The process cannot access the file`).
  Переименование соседних папок при этом проходит. Переименовывает пользователь
  вручную, закрыв редактор и сессию: скрипт для этого не нужен.
- **Переименование папки обнуляет историю сессий Claude Code.** Каталог в
  `~/.claude/projects/` называется слагом абсолютного пути, поэтому после
  переименования проект считается новым: `--resume` и `--continue` старую
  сессию не найдут. Именно поэтому весь контекст живёт в `CLAUDE.md` и
  `PLAN.md`, а не в истории диалога. **Решено отложить переименование до
  конца работ** — имя локальной папки ни на что не влияет, репозиторий уже
  называется `voxduo`.
- **Обратные слеши и heredoc.** Одинарный слеш доезжает до файла целиком —
  регулярки вида `re.compile(r"\s+")` пишутся нормально. А вот удвоенный
  схлопывается в одинарный, отсюда `SyntaxWarning: invalid escape sequence`.
  Отдельная ловушка: во вспомогательных скриптах-патчерах строки поиска надо
  делать raw (`r'''...'''`) или собирать слеш через `chr(92)` — иначе `\b`
  превращается в символ backspace и `assert old in s` падает без объяснений.
  В путях внутри Python использовать прямые слеши или `pathlib`.
- **Не смешивать heredoc и длинный inline-Python в одной команде bash.**
  Кавычки внутри проверочного скрипта ломают парсинг, и файл не создаётся вовсе.
  Создание файла и его проверка — разными вызовами.
- **PowerShell здесь — Windows PowerShell 5.1:** нет `&&`, нет тернарного
  оператора; `Get-ChildItem --json`-подобные аргументы `gh` требуют `--%`.
- **Проверять команды нужно из PowerShell, а не только из Bash-инструмента.**
  `just` на Windows по умолчанию ищет `sh`; он есть в
  `C:\Program Files\Git\usr\bin`, но Git не кладёт этот каталог в PATH. Из
  Bash-инструмента рецепты работали, у пользователя в PowerShell — падали с
  `could not find the shell 'sh'`. Лечится `set windows-shell` в `justfile`.
- **`-ErrorAction SilentlyContinue` не делает команду успешной.** Ошибку он
  прячет, но код возврата остаётся 1, и `just` обрывает рецепт на этой
  строке. Проверять `Test-Path` перед удалением, а не глушить ошибки.
- **PyInstaller: три грабли, найденные на этом проекте.**
    1. `importlib.metadata` не видит пакеты внутри бандла — версии показываются
       как «не установлен». Лечится `copy_metadata()` в spec.
    2. CTranslate2 сообщает о видеокарте по одному драйверу, без cuBLAS рядом.
       Собранное приложение обещало GPU и упало бы посреди распознавания;
       `cuda_setup` теперь проверяет `sys.frozen` и уходит на процессор.
    3. `collect_data_files` тянет всё подряд: у Piper приехали данные для
       иврита и арабского, 26 МБ ненужных языков.
- **Файлы .ps1 с кириллицей нужны в UTF-8 с BOM.** Windows PowerShell 5.1
  без BOM читает файл в ANSI, русский текст в строках превращается в мусор, и
  скрипт падает с синтаксическими ошибками вроде «отсутствует закрывающий
  токен». Плюс `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8` в
  начале скрипта, иначе вывод в консоль всё равно кракозябры.
- **Большие файлы писать не через heredoc.** Bash срывается на парсинге
  длинных вставок с кириллицей и кавычками, и файл не создаётся вовсе, молча.
  Для модулей больше сотни строк использовать запись файла напрямую.
- **Собранное PyInstaller приложение буферизует stdout в канал.** Читать из
  него через `readline()` бесполезно: вывод приходит только когда процесс
  завершится, а до тех пор читающая сторона висит. `PYTHONUNBUFFERED` не
  помогает — в бандле это уже не обычный запуск Python. Решение: приложение
  публикует нужное (порт, состояние) в файл, читатель берёт оттуда.
- **`terminate()` не закрывает окно pywebview.** GUI-цикл мягкий сигнал может
  не обработать, и процесс остаётся висеть вместе с окном. В скриптах,
  которые запускают приложение для проверки, — только `kill()`.
- **У каждого действия должен быть заметный отклик.** В проверочной сборке
  кнопка отрабатывала верно, но пользователь решил, что «ничего не произошло»:
  результат появлялся тихим текстом, сама кнопка не менялась, анимации не было.
  Правило для интерфейса: нажатие меняет состояние кнопки, результат
  появляется с анимацией. Тихое изменение текста проходит мимо взгляда.
- **Консоль не показывает кириллицу корректно** (cp866), но файлы пишутся в
  UTF-8 — проверять кодировку, а не доверять выводу.
